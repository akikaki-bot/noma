# 数値型と実行規則

この仕様は実装言語から独立したNomaの数値規則を定める。TypeScript処理系は整数を内部で`bigint`、浮動小数点を`number`で保持する。NomaにはBigIntという公開型も任意精度整数型も存在しない。将来のVM・Wasm・ネイティブ実装も、次の値域・計算結果・エラーを再現する必要がある。

## 型と値域

| 型 | ビット幅 | 最小値 | 最大値 |
| --- | --- | --- | --- |
| int8 | 8 | -128 | 127 |
| int16 | 16 | -32768 | 32767 |
| int32 | 32 | -2147483648 | 2147483647 |
| int64 | 64 | -9223372036854775808 | 9223372036854775807 |
| uint8 | 8 | 0 | 255 |
| uint16 | 16 | 0 | 65535 |
| uint32 | 32 | 0 | 4294967295 |
| uint64 | 64 | 0 | 18446744073709551615 |

型注釈は引き続き必須。10進整数リテラルはソース文字列から正確に解析し、期待型があればその整数型の値域を検査する。期待型のない整数式は既存互換のint32とする。関数引数・戻り値・配列要素・構造体フィールド・算術式にも同じ規則を適用する。型引数は完全に明示する。従来は10進整数のみであり、今回も16進・2進構文は追加しない。

```noma
fn identity<T>(value:T)->T{return value;}
fn main()->void{
 let minimum:int64=-9223372036854775808;
 let maximum:uint64=identity<uint64>(18446744073709551615);
 let small:uint8=200;
 let wide:uint16=(uint16)small;
}
```

異なる具体的な数値型の暗黙変換・整数昇格はない。整数と浮動小数点の暗黙混合もない。`uint8 + uint16`は結果の注釈に関係なくコンパイルエラー。数値の比較も同じ具体型を要求する。リテラルの文脈付けは既存変数の型を変更しない。Union・match・trycast・snapshot・Generics・Future・Nativeの通過後も、整数幅とfloat32/64の具体型を保持する。

## 演算とエラー

`+`、`-`、`*`、`/`、`%`、単項`-`、後置`++`・`--`の結果はオペランドと同じ型。演算の各段階で結果が値域に収まるか検査する。ラップアラウンド・飽和・ビット切り詰めは行わない。`++`・`--`は変更前の値を返す。現在ビット演算・シフト演算は未実装。

整数除算は0方向への切り捨て、剰余は被除数と同じ符号（または0）。`-7 / 3 == -2`、`-7 % 3 == -1`。符号付き最小値の`/-1`と単項マイナスはオーバーフロー。符号なしの`0-1`もエラー。整数の`/0`・`%0`は禁止。

リテラル・算術・キャスト・snapshotで構成される定数式の確定エラーはコンパイル時に診断する。変数や関数を使う式は実行時に検査する。定数変数の伝播や関数のコンパイル時実行は行わない。未実行の短絡分岐でも、不正な定数式は診断対象となる。Debug/Releaseで規則は変わらず、現在の処理系には演算規則を変更するモード自体がない。

実行時のオーバーフロー・ゼロ除算・不正な数値キャストは位置付きRuntime Errorとして停止する。`catch`・`otherwise`で回復するthrowableとは異なる。既存の`checkedAddInt32`・`checkedSubInt32`・`checkedMulInt32`は従来どおり`int32 | throwable`を返し、通常演算のRuntime Errorを経由しない。`raise`の仕様は変更しない。

## 明示的キャストと浮動小数点

`(uint16)value`のようなキャストだけで数値型を変更できる。整数間のキャストは値を保存し、変換先の値域を超えた場合はエラー。定数で確定する場合はコンパイル時に拒否する。`typing.trycast`は従来どおり型の検査と構造射影であり、数値変換は行わない。

`float32`はIEEE 754 binary32、`float64`はbinary64。小数・指数構文（`1.0`、`1e3`）を受け付け、文脈のない浮動小数点リテラルはfloat64。float32はリテラル・演算結果・キャストで32bit精度に丸める。整数リテラルをfloat注釈だけで暗黙変換しない。`+Infinity`・`-Infinity`・`NaN`・`+0.0`・`-0.0`を保持し、浮動小数点のゼロ除算はIEEE規則に従う（例:`1.0/0.0`、`0.0/0.0`）。

調査時点ではfloat型も数値キャストも未実装だったため、今回次の正式規則を定めた。浮動小数点→整数は、有限・小数部分なし・変換先整数の値域内という3条件をすべて満たす場合だけ許可する。整数→float32/64は元の数学的整数値を正確に表現できる場合だけ許可する。小数・NaN・Infinity・整数値域外・精度を失う整数→floatキャストはRuntime Error（定数ならコンパイル時診断）。暗黙の切り捨て・四捨五入・飽和変換を行わない。float32/64間の明示キャストは変換先のIEEE精度に丸める。

64bit整数の正確性は元の整数を保持したまま、変換先浮動小数点値を整数へ戻して比較する。`9007199254740992`→float64は許可し、`9007199254740993`→float64は拒否する。`16777216`→float32は許可し、`16777217`→float32は拒否する。通常のfloatリテラル・演算はIEEE丸めを行うため、例えばfloat32の`16777216.0+1.0`は`16777216.0`となる。意図的な精度損失は将来`std/number`の専用関数で明示する方針であり、今回その関数は追加しない。

## 標準ライブラリ・ホスト境界

`std/number.toString`は全10数値型を受け付け、64bit整数も正確な10進文字列にする。`std/io`は従来どおり文字列を出力する。既存のint32用パース・文字列化・checked APIは保持する。他の整数型ごとのパース関数は追加しない。配列と文字列のindex APIは既存互換のint32であり、ホスト配列操作では非負・長さ・安全整数範囲を検証してからホストindexへ変換する。

TypeScript Native APIでは整数の入出力を`bigint`にする。`number`を整数値として返す旧ホストコードは契約違反になる。これはNoma言語の公開型変更ではなく、ホスト実装用ABIの移行である。通常のNoma整数演算に`BigInt.asIntN`・`BigInt.asUintN`は用いない。

複数の整数型またはfloat32/64を含むNativeのUnion戻り値は、`new NativeValue(rawValue, concreteType)`で具体型を明示する。`NativeRegistry.callTyped()`は`{value,type}`を返し、従来の`call()`は値だけを返す。配列・構造体の数値Union要素も具体型を保持する。型情報が不足したホスト値は値域から幅を推測せず契約違反として拒否し、float32のホスト値はbinary32精度であることも検証する。

コンパイラAST等のJSON化には`numericJsonReplacer`／`numericJsonReviver`を使用し、整数をタグ付き10進文字列で保存する。リテラルの元の文字列・型構文もASTに残す。LSPはASTやRuntime値を送らず、文字列の型説明・診断・位置だけをJSON-RPCへ送信する。

Runtime値を保存・交換する場合は`serializeValue(value,type)`／`deserializeValue(json)`を使用する。バージョン付き形式で具体的なNoma型と正確な整数文字列を保存し、配列・構造体の各要素の数値型も復元する。floatのNaN・±Infinity・-0も保持する。複数数値型のUnionに属する単体値を保存するときは具体型を渡す（値域から整数幅を推測しない）。Futureの実行状態等のopaque値は保存対象外とする。
